# Android SAF Media and Lesson Notes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Play selected SAF video lessons with subtitles and read/create/update canonical Markdown lesson notes safely on Android while preserving desktop behavior.

**Architecture:** Extend the repository-local SAF plugin with an opaque-ID resolver, tokenized loopback range transport, bounded subtitle reads, and verified note I/O. Keep Vidstack and the completed mobile UI, share pure matching/conversion/identity logic, and retain all raw SAF state in Kotlin.

**Tech Stack:** React 19, TypeScript, Vitest, Vidstack, Tauri 2, Rust, Kotlin/Android ContentResolver/DocumentsContract, Android SAF.

## Global Constraints

- Preserve every existing uncommitted change; do not commit or push.
- Keep desktop `AppShell`, PathBuf scanner, desktop media server, terminal, and note behavior intact.
- Do not modify `.learningappoffline/` or real user course content.
- Do not expose/log SAF identifiers, paths, course/lesson names, note/subtitle content, or licensed metadata.
- Do not request broad storage/media permissions or `MANAGE_EXTERNAL_STORAGE`.
- Use tests first and observe each focused test fail for the intended missing behavior before production changes.
